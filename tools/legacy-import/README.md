# نقل البيانات من النظام القديم

## المرحلة الحالية: دراسة القاعدة القديمة

`Export-LegacySample.ps1` يقرأ قاعدة النظام القديم دون أي تعديل عليها، ويصدّر عينة صغيرة من كل جدول مهم مع ملخصات.
الأسماء والهواتف والعناوين تُخفى افتراضيًا داخل SQL نفسه.

```powershell
powershell -ExecutionPolicy Bypass -File .\Export-LegacySample.ps1
```

الناتج ملف `legacy-sample.zip` على سطح المكتب.

> كل الاستعلامات مجرَّبة على نسخة مطابقة لهيكل القاعدة القديمة (71 جدولًا) على SQL Server.

## أداة النقل داخل النظام الجديد (جاهزة)

**إعدادات النظام ← النقل من نظام الرحمة** (للأدمن). تقرأ قاعدة الرحمة مباشرة من نفس SQL Server (قراءة فقط) وتنقل
**البيانات الأساسية والأرصدة الافتتاحية**؛ السجل التاريخي يبقى في القاعدة القديمة.

| في نظام الرحمة | في النظام الجديد |
|---|---|
| المنتجات `330*20` و`330*40` | صنفان بالقطعة + مستوى شرنك/كارتون، سعر القطعة = آخر سعر عبوة ÷ عددها، ووصفة للقطعة من `KulafManefactuerTable` |
| دفعات المواد (`RawDetelsProudectTable`) | صنف لكل (نوع، اسم خاص/لون): امبولة، سدادة لكل لون، ليبل عام وليبل لكل اسم خاص… برصيد افتتاحي = مجموع المتبقي، والكلفة = سعر آخر دفعة |
| الاسم الخاص (الستيكر) | وصفة مخصصة تستبدل الليبل العام، مربوطة بالعميل المطابق اسمه؛ ملصقات المناسبات عامة |
| المنتج التام (`entajdetels`) | تشغيلة افتتاحية لكل (منتج، ملصق، لون) = المتبقي المسجل، مع عرض المحسوب من الحركات للمقارنة |
| `Customer.deon` | رصيد افتتاحي يدخل كشف العميل وتوزيع الدفعات (الأقدم أولًا)، ولا يُحسب مبيعات |
| التأمينات (`EstelamAmanat` − `TaslemAmanat`) | رصيد تأمين افتتاحي (التزام، منفصل عن الدين) |
| `Supplier.deon` | ذمة دائنة افتتاحية (أو دفعة مقدمة إن كانت سالبة) |
| الموظفون الفعّالون، الأقسام، الشفتات | كما هي، والسلف (`SlafTabel`) رصيد افتتاحي بقسط شهري (آخر قسط استُقطع) |
| `kasat` | صندوق لكل صندوق قديم برصيد = **الجرد الفعلي** الذي يدخله المستخدم؛ واحد منها يصبح الصندوق الرئيسي |

الخطوات: تحليل ← مراجعة وتعديل (الجرد، الكميات، الربط، الأقساط) ← **تجربة ومطابقة** (ينفّذ كل شيء ثم يتراجع ويعرض
كل رقم قديم مقابل ما سُجّل فعلًا) ← **تنفيذ** يُحفظ فقط إن تطابقت كل الأرقام، ولا يتكرر على نفس المشروع.

المستخدمون لا يُنقلون: يُنشأون من جديد بكلمات مرور جديدة.

## استعادة نسخة احتياطية أحدث

`Restore-NewerBackup.sql` يستعيد ملف ‎.bak‎ باسم قاعدة جديدة (افتراضيًا `ALRAHMA_NEW`) بجانب القاعدة الحالية دون المساس بها،
وينقل ملفاتها بأسماء جديدة حتى لا تتعارض، ثم يعرض آخر تاريخ فاتورة وإنتاج ودفعة للتأكد أنها الأحدث.
يُفتح في SSMS، ويُعدَّل فيه سطرا المسار والاسم فقط، ثم Execute.
