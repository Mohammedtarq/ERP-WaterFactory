# دليل تجهيز الشبكة — سيرفر واحد وعدة أجهزة

النظام الجديد يعمل بنفس فكرة نظامكم القديم:
- **جهاز السيرفر** فيه SQL Server وكل البيانات.
- **كل جهاز آخر** فيه البرنامج فقط، ويتصل بالسيرفر عبر الشبكة (كيبل LAN أو Wi-Fi).

لا حاجة لسيرفر جديد. الجهاز الحالي `DESKTOP-1DS408L` فيه SQL Server Express، وقاعدة النظام القديم والجديد تعملان عليه جنبًا إلى جنب دون أن تتداخلا.

```
                ┌─────────────────────────────────────┐
                │  السيرفر  DESKTOP-1DS408L            │
                │  SQL Server Express (SQLEXPRESS)     │
                │   ├─ ALRAHMA…        (النظام القديم)  │
                │   ├─ ERP_ControlDB   (النظام الجديد)  │
                │   └─ ERP_Basra_V2    (بيانات المعمل)  │
                └──────────────┬──────────────────────┘
                     الراوتر / السويتش
        ┌──────────────┬───────┴──────┬──────────────┐
     المحاسبة        المبيعات        المخازن        الإنتاج
   (البرنامج فقط)  (البرنامج فقط)  (البرنامج فقط)  (البرنامج فقط)
```

## الجزء الأول: جهاز السيرفر (مرة واحدة)

### الطريقة السريعة: السكربت الجاهز (موصى بها)
في حزمة البرنامج مجلد اسمه **الشبكة**، وفيه الملف `Setup-SqlServerForLan.ps1`.

1. انسخ المجلد إلى سطح المكتب في جهاز السيرفر.
2. اضغط زر **ابدأ**، واكتب `PowerShell`، ثم اضغط عليه بزر الفأرة الأيمن واختر **Run as administrator**.
3. اكتب هذا الأمر (عدّل المسار إن كان مختلفًا)، ثم اضغط Enter:
   ```powershell
   powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\الشبكة\Setup-SqlServerForLan.ps1"
   ```
4. يطلب منك كلمة مرور لمستخدم البرنامج `erp_app`. اختر كلمة مرور قوية من 8 أحرف أو أكثر واحفظها، فستحتاجها في كل جهاز.
5. في النهاية يطبع لك **اسم السيرفر** الذي تكتبه في الأجهزة الأخرى، مثل:
   ```
   اسم السيرفر:  DESKTOP-1DS408L\SQLEXPRESS
          أو:     192.168.1.10\SQLEXPRESS
   مستخدم SQL Server:  erp_app
   ```

**ما يفعله السكربت.** لا يحذف ولا يعدّل أي بيانات.

| الخطوة | لماذا |
|---|---|
| يفعّل TCP/IP ويثبّت المنفذ 1433 | ليسمع SQL Server طلبات الأجهزة الأخرى |
| يفعّل المصادقة المختلطة | ليُقبل الدخول بمستخدم SQL (`erp_app`) من أي جهاز |
| يشغّل خدمة SQL Server Browser | لتعمل كتابة `SERVER\SQLEXPRESS` من الأجهزة الأخرى |
| يفتح TCP 1433 وUDP 1434 في جدار الحماية | **للشبكة المحلية فقط**؛ الإنترنت لا يصل |
| يعيد تشغيل SQL Server | لتطبيق الإعدادات. يتوقف النظامان القديم والجديد ثوانيَ قليلة، فشغّله خارج وقت العمل |
| ينشئ المستخدم `erp_app` | صلاحية كاملة على قواعد `ERP_*` فقط، و**قراءة فقط** على قواعد `ALRAHMA*` لأداة النقل |

> إن كانت أجهزة الشبكة تستخدم أصلًا مستخدم SQL للنظام القديم فلا مشكلة، فالمستخدمان منفصلان.

### الطريقة اليدوية (إن لم يعمل السكربت)
1. **TCP/IP:**
   - افتح **SQL Server Configuration Manager**. إن لم تجده، اكتب في ابدأ `SQLServerManager16.msc` أو `SQLServerManager15.msc`.
   - اذهب إلى **SQL Server Network Configuration** ← **Protocols for SQLEXPRESS** ← **TCP/IP**، واجعله **Enabled**.
   - في تبويب **IP Addresses** ← **IPAll**: امسح **TCP Dynamic Ports**، واكتب `1433` في **TCP Port**.
2. **SQL Server Browser:** من **SQL Server Services**، زر يمين ← **Properties** ← **Service** ← **Start Mode = Automatic**، ثم **Start**.
3. **أعد تشغيل** خدمة **SQL Server (SQLEXPRESS)**: زر يمين ← **Restart**.
4. **جدار الحماية:** من **Windows Defender Firewall** ← **Advanced settings** ← **Inbound Rules** ← **New Rule**:
   - Port ← TCP ← `1433` ← Allow.
   - كرر لـ UDP ← `1434`.
5. **المصادقة المختلطة ومستخدم البرنامج:** من **SSMS**:
   - زر يمين على السيرفر ← **Properties** ← **Security** ← **SQL Server and Windows Authentication mode**، ثم أعد تشغيل الخدمة.
   - **Security** ← **Logins** ← **New Login** ← الاسم `erp_app` ← **SQL Server authentication** ← كلمة المرور، وأزل علامة **Enforce password policy**.
   - في **Server Roles** اختر `dbcreator`.
   - في **User Mapping** اختر `ERP_ControlDB` و`ERP_Basra_V2` مع `db_owner`، واختر قاعدة الرحمة مع `db_datareader`.

### نصائح مهمة لجهاز السيرفر
- **عنوان IP ثابت:** من إعدادات الراوتر، احجز عنوانًا ثابتًا لجهاز السيرفر (DHCP Reservation)، وإلا قد يتغير عنوانه بعد إعادة التشغيل.
- **أوقف السكون:** من **Settings** ← **Power** ← **Sleep** ← **Never**. السيرفر النائم يعني أن كل الأجهزة متوقفة.
- **النسخ الاحتياطي يبقى على السيرفر:** من البرنامج: إعدادات النظام ← النسخ الاحتياطي. انسخ ملفات `.bak` أسبوعيًا إلى فلاش أو قرص خارجي.
- **UPS:** انقطاع الكهرباء المفاجئ على السيرفر أخطر ما يهدد البيانات. جهاز UPS صغير يكفي لإطفاء آمن.

## الجزء الثاني: كل جهاز مستخدم (5 دقائق للجهاز)

1. انسخ مجلد البرنامج `ERP-WaterFactory-win-x64` إلى `C:\ERP`. يمكنك نسخه من فلاش أو من مجلد مشترك على السيرفر.
2. اضغط زر يمين على `ERP.Desktop.exe` ← **Send to** ← **Desktop (create shortcut)**.
3. شغّل البرنامج. يظهر **معالج الإعداد** في المرة الأولى فقط:

   | الحقل | ما تكتبه |
   |---|---|
   | اسم السيرفر | `DESKTOP-1DS408L\SQLEXPRESS`، أو `192.168.1.10\SQLEXPRESS`، أو `192.168.1.10,1433` |
   | المصادقة | **مستخدم SQL Server** |
   | اسم المستخدم / كلمة المرور | `erp_app` وكلمة المرور التي اخترتها |
   | قاعدة التحكم المركزية | اتركها `ERP_ControlDB` |

4. اضغط **فحص الاتصال**، فيجب أن تظهر رسالة خضراء.
5. اختر **الاتصال بنظام مثبّت مسبقًا على هذا السيرفر** ← **تنفيذ الإعداد والمتابعة**.
6. تظهر شاشة الدخول. يدخل كل موظف **باسمه وكلمة مروره في النظام** (يُنشئها المدير من إعدادات النظام ← المستخدمون)، وليس بـ `erp_app`.

> **الفرق بين المستخدمَين:** `erp_app` هو مفتاح الجهاز للوصول إلى قاعدة البيانات، ويُكتب مرة واحدة في المعالج. أما اسم الموظف وكلمة مروره فهما ما يحدد صلاحياته داخل البرنامج: المبيعات تفتح المبيعات فقط، والمخازن تفتح المخازن فقط، وهكذا.

**على جهاز السيرفر نفسه** (إن كان أحد يعمل عليه): نفس الخطوات، واسم السيرفر `.\SQLEXPRESS`، ويمكن اختيار مصادقة Windows.

## الجزء الثالث: النظامان معًا أثناء فترة التعلّم

- النظام القديم يستمر كما هو تمامًا. لا شيء في الخطوات أعلاه يغيّر قاعدة الرحمة.
- النظام الجديد يُجرَّب أولًا في **مشروع تجريبي**: من إعدادات النظام ← **المشاريع والشركات** ← مشروع جديد، باسم مثل `ERP_Trial`، ثم اختره من شاشة الدخول. تُنقل إليه بيانات الرحمة بأداة النقل، فتتدربون عليه دون خطر.
- **يوم الانتقال الفعلي:**
  1. إيقاف الإدخال في النظام القديم.
  2. نسخة احتياطية من قاعدة الرحمة.
  3. النقل إلى المشروع الحقيقي.
  4. مراجعة تقرير المطابقة (الأرصدة في النظامين متطابقة).
  5. البدء.

## حل المشكلات

| ما يظهر | السبب والحل |
|---|---|
| **تعذّر الاتصال بالسيرفر** من جهاز آخر، ويعمل على السيرفر نفسه | جدار الحماية أو TCP/IP. شغّل السكربت مرة أخرى كمسؤول. وإن كان على السيرفر برنامج حماية (مثل ESET أو Kaspersky) فله جدار حماية خاص، فاسمح فيه بالمنفذين 1433 و1434 |
| يعمل بعنوان IP ولا يعمل باسم الجهاز | مشكلة أسماء في الشبكة. استخدم عنوان IP الثابت في المعالج |
| يعمل `IP,1433` ولا يعمل `IP\SQLEXPRESS` | خدمة SQL Server Browser متوقفة، أو المنفذ UDP 1434 مغلق |
| **Login failed for user 'erp_app'** | كلمة المرور خطأ، أو المصادقة المختلطة لم تُفعَّل (أعد تشغيل خدمة SQL Server بعد تفعيلها) |
| يعمل صباحًا ويتوقف بعد الظهر | السيرفر دخل وضع السكون، أو تغيّر عنوان IP |
| بطء ملحوظ عبر Wi-Fi | يُفضَّل كيبل LAN لجهاز السيرفر على الأقل |

**فحص سريع من أي جهاز:** افتح PowerShell واكتب الأمر التالي. إن ظهر `TcpTestSucceeded : True` فالشبكة والمنفذ سليمان:
```powershell
Test-NetConnection 192.168.1.10 -Port 1433
```

مكان إعداد الاتصال على كل جهاز: `%AppData%\ERP-WaterFactory\appsettings.json`. احذفه لتغيير السيرفر وإعادة تشغيل المعالج.
