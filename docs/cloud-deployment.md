# المزامنة السحابية — دليل التشغيل والنشر

> المرحلة 1 من خطة التكامل (`docs/integration-plan.md`). **1-أ** (منفَّذة): الخادم والخدمة والشاشة، مختبرة على الجهاز.
> **1-ب** (عند فتح الحساب): الرفع على Azure بالخطوات أدناه.

## كيف تعمل
```
هاتف المندوب ──HTTPS──► الخادم السحابي (ERP.Cloud.Api + قاعدة وسيطة صغيرة)
                                ▲
                                │ اتصال صادر فقط، كل 20 ثانية (قابل للتعديل)
                       خدمة المزامنة على جهاز السيرفر (ERP.SyncAgent)
                                │
                       قاعدة المعمل = الأصل: كل حركة تُرحَّل بخدمات النظام نفسها
```
| المكوّن | المشروع | ماذا يفعل |
|---|---|---|
| الخادم السحابي | `ERP.Cloud.Api` | صندوق بريد: يحفظ حركات الهواتف حتى يسحبها المعمل، ويعيد نتائجها و«نسخة عمل» كل مندوب. لا حسابات ولا قيود فيه |
| خدمة المزامنة | `ERP.SyncAgent` | خدمة Windows على جهاز السيرفر: ترفع بصمات الأجهزة، وتسحب الحركات وترحّلها بـ `RepAppService`، وتعيد النتائج، وترفع نسخ العمل إن تغيّرت |
| المنطق المشترك | `ERP.Data/Services/CloudSyncService.cs`، `CloudSyncRunner.cs` | الدورة نفسها تعمل من الخدمة أو من زر «مزامنة الآن» |
| العقود | `ERP.Cloud.Contracts` | شكل الرسائل للهاتف والخادم والخدمة (يستخدمه تطبيق الهاتف في المرحلة 2) |

**ضمانات:**
- **لا منفذ مفتوح في المعمل:** الخدمة هي التي تتصل بالخادم.
- **لا ضياع ولا تكرار:** لكل حركة رقم فريد، وإعادة الإرسال تعيد النتيجة المحفوظة.
- **انقطاع الإنترنت:** تنتظر الحركات في الخادم.
- **الأجهزة:** الخادم يحفظ بصمة مفتاح الجهاز (SHA-256) لا المفتاح نفسه. إيقاف الجهاز في «أجهزة التطبيق» يصل الخادم في الدورة التالية، ويُعاد التحقق منه في المعمل عند الترحيل.
- **حدود الحجم:** المحتوى حتى 64KB، والصورة حتى 3MB. صور الوصولات تُحذف من الخادم فور وصولها للمعمل، والحركات المنتهية تُحذف بعد 30 يومًا.

## في النظام: «الإعدادات ← المزامنة السحابية»
1. **توليد مفتاح جديد:** انسخ المفتاح فورًا، فهو يُعرض مرة واحدة. يُلصق في إعداد الخادم `Relay__AgentKey`.
2. **عنوان الخادم:** مثل `https://api.alrahma-water.com`. يُقبل `https` فقط، و`http` لجهاز محلي للتجربة.
3. **الفترة:** الافتراضي 20 ثانية، والمسموح بين 5 و600.
4. ضع علامة **تفعيل المزامنة السحابية**، ثم اضغط **حفظ**.
5. **اختبار الاتصال** يتحقق من الخادم والمفتاح. **مزامنة الآن** تجري دورة واحدة من هذا الجهاز.

الشاشة تعرض آخر مزامنة ناجحة، وآخر خطأ، وعدد الحركات الواصلة، وآخر تحديث لنسخ العمل. ويظهر مؤشر صغير أسفل الشريط الجانبي (أخضر / برتقالي / أحمر) عند التفعيل.

## تثبيت خدمة المزامنة على جهاز السيرفر (مرة واحدة، كمسؤول)
الخدمة موجودة في مجلد البرنامج: `SyncAgent\ERP.SyncAgent.exe`. من موجه أوامر **كمسؤول**:
```
"C:\Program Files\ERP-WaterFactory\SyncAgent\ERP.SyncAgent.exe" --install --control "Server=localhost\SQLEXPRESS;Database=ERP_ControlDB;Integrated Security=True;TrustServerCertificate=True"
```
- **سلسلة الاتصال:** نفس سلسلة قاعدة التحكم في `%AppData%\ERP-WaterFactory\appsettings.json` على جهاز السيرفر.
- **ما يفعله التثبيت:**
  1. يحفظ الإعداد في `%ProgramData%\ERP-WaterFactory\sync-agent.json`، للمسؤولين والخدمة فقط.
  2. ينشئ خدمة `ERPCloudSync` بحساب الخدمة الخاص `NT SERVICE\ERPCloudSync`، تبدأ مع Windows وتُعاد تلقائيًا إن توقفت.
  3. مع مصادقة Windows: يمنح حساب الخدمة القراءة والكتابة والتنفيذ في قاعدة التحكم وقواعد المشاريع.
  4. يشغّل الخدمة.
- **للتجربة دون تثبيت:** `ERP.SyncAgent.exe --once` يجري دورة واحدة ويطبع النتيجة.
- **الإزالة:** `ERP.SyncAgent.exe --uninstall`.
- **أكثر من مشروع:** الخدمة تمر على كل مشاريع قاعدة التحكم الفعّالة، وتزامن ما فُعّلت فيه المزامنة فقط.

## 1-ب: النشر على Azure (عند فتح الحساب)
| الخطوة | التفصيل |
|---|---|
| 1. مجموعة موارد | المنطقة: UAE North |
| 2. قاعدة وسيطة | Azure SQL Database، الفئة Basic (5 DTU). الخادم يُنشئ جداوله بنفسه في أول تشغيل |
| 3. خادم التطبيق | App Service، نظام Linux، ‎.NET 9، الخطة B1 |
| 4. الإعدادات (Environment variables) | `ConnectionStrings__Relay` = سلسلة اتصال القاعدة الوسيطة؛ `Relay__AgentKey` = مفتاح المعمل من الشاشة |
| 5. الحماية | HTTPS Only = تشغيل، وTLS 1.2 فأعلى، وFTP = إيقاف |
| 6. فحص الصحة | Health check path = `/api/health` |
| 7. النطاق | ربط النطاق (مثل `api.alrahma-water.com`) بشهادة مُدارة مجانية |
| 8. الرفع | الحزمة `ERP-Cloud-Api` من تبويب Actions (Artifacts) ← Deployment Center أو `az webapp deploy` |
| 9. النسخ الاحتياطي | Azure SQL يحتفظ تلقائيًا بنسخ 7 أيام. القاعدة الوسيطة ليست الأصل، فالأصل قاعدة المعمل |

بعد الرفع: الصق العنوان في شاشة «المزامنة السحابية»، ثم «اختبار الاتصال»، ثم التفعيل والحفظ.

## واجهة الهاتف (للمرحلة 2)
كل طلب يحمل الترويسة `X-Device-Key: <مفتاح الجهاز من «أجهزة التطبيق»>`.

| الطلب | الغرض |
|---|---|
| `POST api/rep/requests` | إرسال حركة `{clientId, kind, occurredAt, payload, photo}`. النوع: CashSale، CreditSale، Free، Collection، NewCustomer، Expense، Return. المحتوى: عقود `RepAppService` (SalePayload…) بصيغة JSON |
| `POST api/rep/requests/status` | حالة حركات سابقة `{clientIds:[…]}`. الحالة `Waiting` = لم تصل المعمل، و`Done` معها `status`: Posted / Pending / Rejected / Failed، والرسالة |
| `GET api/rep/snapshot` | نسخة العمل (`RepSnapshot`): الزبائن وأرصدتهم وحدودهم، والأصناف بعبواتها وأسعارها، ورصيد السيارة والمحفظة. تدعم `If-None-Match`، فلا تُنزَّل إن لم تتغير |
| `GET api/rep/ping` | آخر اتصال للمعمل («المعمل متصل قبل دقيقتين») |

**قواعد:**
- الحركة المتعذّرة (Failed) تُصحَّح وتُرسل بالرقم نفسه فتُعاد محاولتها.
- رقم حركة جهاز آخر يُرفض (409).
- الجهاز الموقوف يُرفض (401).

## عند ظهور مشكلة
| الرسالة | السبب والحل |
|---|---|
| «مفتاح المعمل غير صحيح» | المفتاح في الخادم يختلف عن الشاشة: الصق المفتاح الحالي في `Relay__AgentKey`، أو ولّد مفتاحًا جديدًا والصقه |
| «مفتاح المعمل غير مضبوط في إعدادات الخادم» | `Relay__AgentKey` فارغ أو قصير |
| «تعذّر الاتصال بالخادم السحابي» | الإنترنت أو العنوان. الحركات تنتظر في الخادم ولا تضيع |
| «لم تتم أي مزامنة بعد» | الخدمة غير مثبّتة أو موقوفة: `services.msc` ← ERP Cloud Sync، أو جرّب `--once` |
| «آخر مزامنة قبل … هل الخدمة تعمل؟» | الخدمة توقفت أو الجهاز مطفأ |
