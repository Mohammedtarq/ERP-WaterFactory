## ملاحظات تصميمية مهمة

- **الأرصدة كسجل حركة (Ledger) لا كرقم مخزَّن**: جدول `StockTransactions` هو مصدر الحقيقة الوحيد لأي رصيد مخزون؛ الرصيد الحالي = مجموع الحركات (SUM)، وليس عمودًا يُحدَّث يدويًا — هذا يحمي من تضارب التحديثات المتزامنة ويعطي أثرًا كاملًا قابلًا للتدقيق (Audit Trail) لأي حركة.
- **نفس المبدأ في `RepWalletTransactions`**: رصيد محفظة المندوب = مجموع (AmountIn - AmountOut)، وليس رقمًا مخزَّنًا.
- **مفتاحان مؤجلان بين ملف 03 و 08** (`ItemBatches.ProductionOrderId`) تم ربطهما عبر `ALTER TABLE` في نهاية ملف 08 لتفادي التداخل الدائري بين الجدولين.
- **الحقول من نوع Enum** (مثل `WarehouseType`, `TransactionType`) نُفِّذَت كـ `NVARCHAR` + `CHECK CONSTRAINT` بدل جداول Lookup منفصلة، تبسيطًا؛ يمكن تحويلها لجداول مرجعية منفصلة لاحقًا إن احتجتم إدارتها من واجهة المستخدم مباشرة.
- **لم تُكتب بعد**: الفهارس التكميلية (Indexes) الخاصة بالأداء على الجداول عالية الاستخدام (مثل `SalesInvoices`, `AttendanceRecords`)، والـ Views المساعدة (مثل "الرصيد الحالي لكل صنف") — هذه تُضاف عادة بعد بدء الاستخدام الفعلي وملاحظة أنماط الاستعلام الحقيقية، لا قبلها.

## لم يُغطَّ بعد في هذا المخطط (يحتاج قرارًا لاحقًا عند الوصول لتلك المرحلة)

- جداول الشركات الأخرى بعيدًا عن مصنع المياه (كل مشروع مستقبلي يُصمَّم مخططه الخاص حسب طبيعته).
- تفاصيل بوابة الدفع الإلكتروني الفعلية (الحقل موجود في `SalesInvoices.PaymentMethod` كنقطة تمديد فقط).

## وحدة المبيعات — `09_sales_logic.sql`

الواجهة (أي لغة) تستدعي هذه الإجراءات مباشرة، وكل قواعد العمل مطبّقة داخل قاعدة البيانات:

| الإجراء / العرض | الغرض |
|---|---|
| `sp_Sales_CreateInvoice` | إنشاء فاتورة مسودة (يتحقق من العميل، المخزن القابل للبيع، الجهة المستفيدة للمجانية، ويحدد المندوب تلقائيًا من الكاش فان) |
| `sp_Sales_AddInvoiceLine` | إضافة سطر؛ السعر يُحسب تلقائيًا إن لم يُمرَّر (سعر القطعة × عدد القطع في وحدة البيع) |
| `sp_Sales_DeleteInvoiceLine` / `sp_Sales_DeleteDraftInvoice` | تعديل/حذف المسودات فقط |
| `sp_Sales_PostInvoice` | الترحيل الذري: مجاميع + ضريبة + مستلزمات تحميل ← خصم مخزون FIFO ← قيد متوازن مرحّل ← محفظة المندوب |
| `fn_Sales_BaseUnitPrice` | التسعير الهرمي: وكيل ← سعره الخاص؛ عميل فرعي ← سعر وكيله الأب؛ غير ذلك ← سعر البيع العادي |
| `vw_StockBalance` | الرصيد الحالي لكل صنف/مخزن/تشغيلة من سجل الحركة |
| `vw_SalesInvoiceList` / `vw_SalesInvoiceTotals` | شاشة قائمة الفواتير ومعاينة المجاميع قبل الترحيل |
| `vw_CustomerStatement` / `vw_CustomerBalances` | كشف حساب ورصيد كل عميل بشكل مستقل |

**قواعد الربط المحاسبي المطلوبة** (`AccountMappingRules.TransactionType`):
`SalesInvoiceCash`، `SalesInvoiceCredit`، `SalesInvoiceElectronic`، `SalesInvoiceRepCash`، `SalesTax` (الدائن فقط)، `LoadingSuppliesCharge` (الدائن فقط). غياب أي قاعدة مطلوبة يوقف الترحيل برسالة عربية واضحة دون أي أثر جزئي.

**الصلاحيات**: الإجراءات تتحقق من `RolePermissions` للوحدة `Sales` (Add / Edit / Delete / Post).

**المبيعات المجانية**: تخصم المخزون كحركة `FreeIssue` (أو `RepFreeSale` من الكاش فان) باسم الجهة المستفيدة، بلا قيد مالي وبلا أثر على رصيد العميل.
