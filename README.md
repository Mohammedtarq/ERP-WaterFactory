# نظام ERP — مصنع المياه (البصرة)

تطبيق سطح مكتب WPF (.NET 9) + SQL Server، بتصميم متعدد المشاريع: قاعدة تحكم مركزية واحدة (`ERP_ControlDB`) + قاعدة مستقلة لكل مشروع/عميل.

## هيكل المستودع

```
ERP.Solution.sln
ERP.Data/                  الوصول للبيانات (EF Core): الكيانات، السياقات، الخدمات، التشفير
  ControlDb/  ProjectDb/  Services/  Security/
ERP.Presentation/          منطق كل الشاشات (ViewModels) بلا اعتماد على WPF — مختبر آليًا
  Mvvm/  Services/  ViewModels/{Shell,Warehouse,Finance,Suppliers,Sales,Settings}
ERP.Desktop/               التطبيق (WPF): النوافذ والشاشات XAML، الثيم، المحوّلات
  Themes/  Mvvm/  Services/  Views/{Shell,Warehouse,Finance,Suppliers,Sales,Settings}
ERP.SeedTool/              أداة تُشغَّل مرة واحدة لإنشاء مستخدم وبيانات تجريبية
Database/                  سكربتات SQL (تُنفَّذ بالترتيب)
tests/                     اختبارات SQL + تكامل الخدمات + تشغيل الشاشات + فحص ربط XAML
```

## المتطلبات قبل التشغيل
- Visual Studio 2022 (أو أحدث) مع حمل عمل ".NET Desktop Development"
- .NET 9 SDK
- SQL Server (محلي يكفي للتجربة) + SQL Server Management Studio

## خطوات التشغيل بالترتيب

### 1) إنشاء قواعد البيانات
نفّذ في SSMS:
1. `Database/00_control_db.sql` — ينشئ **`ERP_ControlDB`** (مرة واحدة فقط).
2. أنشئ قاعدة بيانات فارغة باسم **`ERP_Project_WaterFactory`**، ثم نفّذ عليها الملفات من `01` حتى `10` بالترتيب.

| # | الملف | المحتوى |
|---|---|---|
| 0 | `00_control_db.sql` | قاعدة التحكم المركزية (مشتركة بين كل المشاريع) |
| 1 | `01_core_and_security.sql` | فروع، أقسام، شفتات، موظفون، سيارات، أدوار وصلاحيات، مستخدمون |
| 2 | `02_finance.sql` | دليل الحسابات، قواعد الربط التلقائي، القيود، السندات، أسعار الصرف |
| 3 | `03_items_warehouses.sql` | الأصناف، التعبيئة، المخازن، المواقع، التشغيلات، سجل حركة المخزون |
| 4 | `04_suppliers_purchasing.sql` | الموردون، أمر الشراء، الاستلام |
| 5 | `05_sales_customers.sql` | العملاء/الوكلاء، تسعير الوكلاء، فاتورة المبيعات |
| 6 | `06_hr_payroll.sql` | الحضور، الرواتب، الترقيات، الحوافز |
| 7 | `07_reps.sql` | محفظة المندوب، المناطق، الزبائن المخصصون |
| 8 | `08_production.sql` | BOM، الوصفات المخصصة، أمر الإنتاج، المختبر، أمر التعبيئة |
| 9 | `09_sales_logic.sql` | **منطق المبيعات**: التسعير الهرمي، الترحيل الذري (مخزون + قيد + محفظة مندوب)، كشف حساب العميل |
| 10 | `10_items_barcode_alert.sql` | عمودا `BarCode` و `MinStockAlertLevel` في `Items` (يطابق `Item.cs`) — آمن للتنفيذ على قاعدة قائمة |

> **على قاعدة موجودة مسبقًا**: يكفي تنفيذ `09` ثم `10` فقط.

### 2) فتح الحل
افتح `ERP.Solution.sln` في Visual Studio.

### 3) تعبئة بيانات تجريبية
عدّل سلسلتي الاتصال أعلى `ERP.SeedTool/Program.cs` إن لزم، ثم: **زر يمين على ERP.SeedTool ← Set as Startup Project ← F5**. الأداة آمنة للتشغيل أكثر من مرة، وتنشئ:
- دور "مدير عام" بكل الصلاحيات + مستخدم `admin` / `Admin@123`
- دليل حسابات + قواعد الربط (السندات، المشتريات، **المبيعات الست، وقيد الرواتب**)
- شفت صباحي افتراضي، وأوزان الحافز 40/30/30، ومقياس حافز **تجريبي** (عدّله حسب المعتمد لديكم)
- مورد، فرع، مخزن، **صنفا مياه** (500 مل بالكارتون، 1.5 لتر بالشرنك) برصيد افتتاحي وأسعار وكيل، و**3 عملاء** (وكيل + عميل فرعي تابع له + زبون مباشر)
- وحدة بيع "قطعة" لأي صنف قديم ليس له وحدة بيع

### 4) تشغيل التطبيق
عدّل `ERP.Desktop/appsettings.json` إن احتجت، ثم **Set as Startup Project ← ERP.Desktop ← F5**.

## الشاشات

| الوحدة (الشريط الجانبي) | التبويبات (تحت تبويب "الرئيسية" ذي البطاقات الملوّنة) |
|---|---|
| لوحة المعلومات | مبيعات ومقبوضات اليوم، ذمم العملاء، تنبيهات المخزون، المسودات، آخر الفواتير |
| المخازن | الأصناف · المخازن · هيكلية التعبئة · مواقع المخزن · الرصيد الحالي · تسوية المخزون · احتياجات التصنيع · إعداد قوائم المواد · إعدادات التنبيهات |
| المبيعات | فاتورة مبيعات · قائمة الفواتير · كشف حساب العميل · العملاء · أسعار الوكلاء · رسوم التحميل |
| الموردون والمشتريات | الموردون · أوامر الشراء · استلام البضاعة · كشف حساب المورد |
| المالية | دليل الحسابات · القيود المحاسبية · السندات · العقل المالي · أسعار الصرف |
| الموارد البشرية | الحضور اليومي · تقييم الحوافز الشهرية · تشغيل الرواتب · الترقيات والعلاوات · الموظفون · الشفتات · الأقسام · إعدادات الحافز الشهري · حافز المندوب · حافز مدير المبيعات |
| إعدادات النظام | الأدوار والصلاحيات · المستخدمون · الفروع |
| المندوبون · الإنتاج | "لم تُبنَ بعد" — المراحل القادمة |

- الشريط الجانبي يعرض فقط الوحدات التي يملك دور المستخدم صلاحية **عرضها**، وأزرار الإضافة/التعديل/الحذف/الترحيل تُفحص لكل وحدة.
- أزرار التعديل والحذف داخل صفوف الجداول تستخدم `{Binding DataContext.EditCommand, ElementName=Root}` على جذر اسمه `Root`.
- لإضافة شاشة: ViewModel في `ERP.Presentation` + UserControl في `ERP.Desktop/Views` + سطر في `Views/ViewMappings.xaml`. شاشات القوائم (CRUD) تُولَّد بنمط موحّد عبر `python3 tools/gen_crud_views.py`.

### قائمة فحص بصري سريعة (5 دقائق على Windows)
1. شاشة الدخول: الاتجاه من اليمين لليسار، ورسالة خطأ عربية عند كلمة مرور خاطئة.
2. الشريط الجانبي: 9 وحدات بأيقونات ملوّنة، والمختارة مظللة.
3. المبيعات ← الرئيسية: 6 بطاقات ملوّنة، الضغط على بطاقة يفتح تبويبها.
4. فاتورة مبيعات: اختر "محل أبو حيدر" ← يظهر شريط "عميل فرعي… يرث سعر وكيله"؛ اختر "ماء 500 مل" ← السعر المقترح 2,400 للكارتون؛ أضف سطرًا، فعّل رسوم التحميل، ثم "ترحيل الفاتورة".
5. كشف حساب العميل ثم المخازن ← الرصيد الحالي: الفاتورة ظاهرة والكمية مخصومة.

## وحدة الموارد البشرية — `ERP.Data/Services/HrService.cs`

كل ثوابت المعادلات في `HrRules` (أعلى الملف) — تعديل أي قاعدة = سطر واحد.

| البند | المعادلة المطبّقة |
|---|---|
| **الحضور** | التأخير = وقت الدخول − بداية الشفت، ويُحسب فقط إذا تجاوز فترة السماح. بلا وقت دخول = غائب (إلا الإجازة المعتمدة) |
| **نقاط الانضباط** | (أيام الحضور × 1 + أيام التأخير × 0.5) ÷ (حاضر + متأخر + غائب) × 100 — الإجازة المعتمدة مستثناة |
| **الحافز الشهري** | المجموع = (الانضباط × وزنه + الأداء × وزنه + المهارات × وزنها) ÷ 100 (الأوزان الافتراضية 40/30/30، مجموعها 100 إلزاميًا)، والمبلغ = شريحة المجموع في مقياس التحويل |
| **حافز المندوب** | Σ (الكمية بالقطعة من فواتيره المرحّلة غير المجانية × حافز القطعة للصنف) |
| **حافز مدير المبيعات** | Σ (الكمية الواقعة في كل شريحة × معدلها) × أيام دوامه الفعلية — الكمية = كل المبيعات المرحّلة غير المجانية للشهر |
| **الراتب الأساسي** | راتب التعيين + كل الزيادات الدائمة السارية حتى نهاية الشهر (من الترقيات والعلاوات، لا يُعدَّل الراتب المخزّن) |
| **البدلات** | المبالغ "لمرة واحدة" السارية داخل الشهر |
| **خصم الغياب** | (الأساسي ÷ 30) × أيام الغياب |
| **الصافي** | الأساسي + البدلات + الحوافز − الخصم |
| **عملتان** | الحوافز تُحسب بالدينار وتُحوَّل لموظفي الدولار بآخر سعر صرف ساري حتى نهاية الشهر؛ التوليد يُرفض إن لم يوجد سعر |
| **الاعتماد** | قيد تلقائي بالدينار (مدين مصروف الرواتب / دائن رواتب مستحقة) عبر قاعدة `PayrollAccrual`، ثم يُقفل الشهر: لا تعديل حضور ولا تقييم ولا إعادة توليد |

## وحدة المبيعات

كل قواعد العمل مطبّقة داخل قاعدة البيانات (`09_sales_logic.sql`)، والتطبيق يستدعيها عبر `ERP.Data/Services/SalesService.cs` — فلا يمكن لأي واجهة تجاوزها.

| في C# (`SalesService`) | في SQL | الغرض |
|---|---|---|
| `CreateInvoiceAsync` | `sp_Sales_CreateInvoice` | فاتورة مسودة؛ يتحقق من العميل، المخزن القابل للبيع، الجهة المستفيدة للمجانية، ويحدد المندوب تلقائيًا من الكاش فان |
| `AddLineAsync` / `DeleteLineAsync` | `sp_Sales_AddInvoiceLine` / `sp_Sales_DeleteInvoiceLine` | السعر يُحسب تلقائيًا إن لم يُمرَّر (سعر القطعة × عدد القطع في وحدة البيع) |
| `PostInvoiceAsync` | `sp_Sales_PostInvoice` | **ترحيل ذري**: مجاميع + ضريبة + مستلزمات تحميل ← خصم مخزون FIFO حسب الصلاحية ← قيد متوازن مرحّل ← محفظة المندوب |
| `DeleteDraftInvoiceAsync` | `sp_Sales_DeleteDraftInvoice` | المسودات فقط؛ المرحّل لا يُحذف |
| `GetSuggestedUnitPriceAsync` | `fn_Sales_BaseUnitPrice` | وكيل ← سعره الخاص؛ عميل فرعي ← سعر وكيله الأب؛ غير ذلك ← سعر البيع العادي |
| `GetInvoiceListAsync` | `vw_SalesInvoiceList` | قائمة الفواتير مع المجاميع والمتبقي |
| `GetCustomerBalancesAsync` / `GetCustomerStatementAsync` | `vw_CustomerBalances` / `vw_CustomerStatement` | رصيد وكشف حساب مستقل لكل عميل (مع رصيد تراكمي) |

الأخطاء تعود كـ `FinanceOperationResult.Fail` برسائل عربية جاهزة للعرض (رصيد غير كافٍ مع الكميات، صلاحية ناقصة، قاعدة ربط ناقصة...) ولا يبقى أي أثر جزئي.

**قواعد الربط المحاسبي المطلوبة** (`AccountMappingRules.TransactionType`): `SalesInvoiceCash`، `SalesInvoiceCredit`، `SalesInvoiceElectronic`، `SalesInvoiceRepCash`، `SalesTax` (الدائن فقط)، `LoadingSuppliesCharge` (الدائن فقط) — تنشئها أداة التزويد تلقائيًا.

**الصلاحيات**: وحدة `Sales` في `RolePermissions` (Add / Edit / Delete / Post) — موظف بلا `CanPost` ينشئ المسودة ولا يرحّلها.

**المبيعات المجانية**: حركة `FreeIssue` (أو `RepFreeSale` من الكاش فان) باسم الجهة المستفيدة، بلا قيد مالي وبلا أثر على رصيد العميل.

## الاختبارات

```bash
./tests/run_tests.sh      # يتطلب Docker فقط
```
يشغّل SQL Server 2022 و .NET 9 في Docker، ثم:
1. ينفّذ `Database/00 → 10` على قاعدة نظيفة و`tests/test_sales.sql` (58 فحصًا: التسعير، الضريبة، التحميل، FIFO، الذرّية عند الخطأ، المجانية، الكاش فان، الصلاحيات، توازن القيود).
2. يبني كل المشاريع **ومنها ERP.Desktop** (بلا أخطاء ولا تحذيرات).
3. `tests/ERP.Data.IntegrationTests`: خدمتا المبيعات والموارد البشرية على قاعدة حقيقية — سيناريو رواتب شهر كامل بأرقام محسوبة يدويًا مسبقًا (زيادة دائمة، مكافأة، غياب، تأخير، حافز شهري، مندوب، مدير مبيعات، موظف بالدولار، اعتماد وقفل).
4. `tests/ERP.Presentation.Tests`:
   - **تشغيل الشاشات فعليًا** (نفس الـ ViewModels التي تربطها نوافذ WPF): دخول ← مشروع ← شريط جانبي ← فاتورة ← ترحيل ← كشف حساب ← خصم مخزون، والمسودات، والبيع المجاني، والصلاحيات، وCRUD، والقيود، والسندات، والمشتريات، ومصفوفة الصلاحيات.
   - **فحص كل `{Binding}` في كل ملف XAML** مقابل خصائص الـ ViewModel الفعلية (WPF لا يكشف الخطأ إلا كحقل فارغ وقت التشغيل)، وأن لكل ViewModel شاشة في `ViewMappings.xaml`.

## ملاحظات تصميمية

- **الأرصدة كسجل حركة (Ledger) لا كرقم مخزَّن**: `StockTransactions` مصدر الحقيقة الوحيد لأي رصيد مخزون، و`RepWalletTransactions` لمحفظة المندوب.
- **مفتاح مؤجل بين 03 و 08** (`ItemBatches.ProductionOrderId`) رُبط عبر `ALTER TABLE` في نهاية 08.
- **الحقول من نوع Enum** نُفِّذت كـ `NVARCHAR` + `CHECK CONSTRAINT`، وتُحوَّل في EF عبر `HasConversion<string>()`.
- **ترقيم المبيعات** بتسلسلات SQL (`SI-2026-000001`، وقيودها `SJ-2026-000001`) — آمن مع المستخدمين المتزامنين.
