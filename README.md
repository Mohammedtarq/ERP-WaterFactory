# المرحلة صفر — البنية الأساسية (تسجيل الدخول + اختيار المشروع + الشريط الجانبي)

## المتطلبات قبل التشغيل
- Visual Studio 2022 (أو أحدث) مع حمل عمل ".NET Desktop Development"
- .NET 10 SDK
- SQL Server (محلي يكفي للتجربة) + SQL Server Management Studio

## خطوات التشغيل بالترتيب

### 1) إنشاء قواعد البيانات
نفّذ في SSMS:
1. ملفات مخطط قاعدة البيانات (المُسلَّمة سابقًا) على قاعدة تُسمّى **`ERP_ControlDB`**: ملف `00_control_db.sql` فقط.
2. أنشئ قاعدة بيانات فارغة جديدة باسم **`ERP_Project_WaterFactory`**، ثم نفّذ عليها الملفات من `01` حتى `08` بالترتيب.

### 2) فتح الحل (Solution)
افتح `ERP.Solution.sln` في Visual Studio. يحتوي 3 مشاريع:
- **ERP.Data** — مكتبة الوصول لقاعدة البيانات (Entity Framework Core) — لا تُشغَّل بمفردها.
- **ERP.Desktop** — التطبيق الفعلي (WPF).
- **ERP.SeedTool** — أداة صغيرة تُشغَّل مرة واحدة فقط لإنشاء مستخدم تجريبي.

### 3) تعبئة بيانات تجريبية
افتح `ERP.SeedTool/Program.cs`، تأكد أن سلسلتي الاتصال بالأعلى تطابقان سيرفرك المحلي (الافتراضي `localhost` يعمل غالبًا لو ثبّتّ SQL Server Developer Edition محليًا)، ثم من Visual Studio: **بزر يمين على مشروع ERP.SeedTool ← Set as Startup Project**، ثم شغّله (F5). سيطبع في النافذة السوداء:
```
اسم المستخدم: admin
كلمة المرور:  Admin@123
```

### 4) تشغيل التطبيق
عدّل `ERP.Desktop/appsettings.json` إن احتجت (نفس سلسلة اتصال `ERP_ControlDB`)، ثم: **بزر يمين على مشروع ERP.Desktop ← Set as Startup Project**، وشغّله (F5). سجّل دخولك بالبيانات أعلاه، اختر مشروع "مصنع المياه - البصرة"، وستظهر الواجهة الرئيسية بشريط جانبي كامل الصلاحيات (لأن أداة التزويد أنشأت دور "مدير عام" بكل الصلاحيات).

## ما تتحقق منه في هذه المرحلة
- [ ] شاشة تسجيل الدخول تعمل وتعرض رسالة خطأ صحيحة عند بيانات خاطئة
- [ ] بعد الدخول الصحيح تظهر شاشة اختيار المشروع
- [ ] بعد اختيار المشروع تُفتح الواجهة الرئيسية، والشريط الجانبي يعرض كل الوحدات التسع
- [ ] الضغط على أي وحدة في الشريط الجانبي يُظهر رسالة "لم تُبنَ بعد" في المنتصف (متوقّع في هذه المرحلة)

## عند ظهور أي خطأ
انسخ رسالة الخطأ **كاملة كما ظهرت** (من نافذة Output أو النافذة المنبثقة) وأرسلها، وسأصلح الكود فورًا.

### ملاحظة محتملة عند أول استعادة حزم (NuGet Restore)
كل ملفات csproj مضبوطة على `Microsoft.EntityFrameworkCore.SqlServer` الإصدار `10.0.0`. بيئتي هنا لا تصل لسجل NuGet لأتحقق من رقم الإصدار الدقيق المتاح فعليًا لحظة قراءتك لهذا الملف. لو ظهر خطأ "Unable to find package" عند أول Build، افتح NuGet Package Manager في Visual Studio وحدّث الحزمة لأحدث إصدار متوافق مع .NET 10 — هذا تعديل رقم واحد في ملف المشروع، لا يمس بقية الكود.
